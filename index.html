Project Overview

工业时序预警，缺的不是模型，是「决策」

传感器数据从不缺预测模型——缺的是一个能理解数据形态、选对范式、诚实评估、并把每一步留痕的决策主体。Onion 把「预测」升级为「智能体决策」：拿到任意时序 CSV,它先分诊该做异常检测还是时序预测,再在冻结的任务定义下建模、交叉验证、生成报告——所有指标由确定性脚本写入文件产物,绝不编造。

Agentic Workflow

三体协作留痕

四阶段门控:init → pre-forecast → forecast → post-forecast,严格按序、不得跳阶段。

Planner

分诊 · 冻结任务

与用户协商任务、按数据形态分诊(异常检测 or 时序预测)、分析规模与不平衡度,冻结不可变的 task.json。

动作空间: ingest_csv · triage · freeze task.json
Forecaster

建模 · 调参 · 评估

在冻结任务下执行 propose→run→evaluate→reflect 循环,只依据验证集反馈,禁止改任务定义、禁止编造指标。

动作空间: fault_warning · forecast_eval · evaluate
Critic

可视化 · 核对 · 报告

核对指标真实性(双脚本交叉验证)、导出大屏数据、生成 final-report。禁止改模型或分数。

动作空间: viz · cross-check · final-report.md

Two Parallel Paths

一套入口，两种交付

ANOMALY

异常检测

  • train 只含正常样本 → 学正常模式,test 检测偏离
  • 异常分 = -IsolationForest.score_samples
  • 有标签 → AUC / recall / F1 / balanced_acc
  • 无标签 → 异常分 + 预警排名(不报有监督指标)
ingest_csv → fault_warning → evaluate →(有标签)viz
FORECAST

时序预测

  • 留出末段真值,用历史调 TimesFM 回测该段
  • 误差指标 MSE / MAE / RMSE / MAPE / sMAPE
  • 分位数覆盖率检验区间标定
  • 对比 persistence 基线给相对改善
forecast_eval → forecast_metrics.json

Quickstart

一条命令，跑通全程

编排层自动分诊 → 选通路 → 串起各脚本 → 汇总产物。指标全部来自文件,不重算、不编造。

onion · pipeline.py复制
# 自动分诊：按数据形态给建议，判据明确则执行
./cc '$PY scripts/pipeline.py --csv data/foo.csv --task auto'

# 异常检测（有标签）→ 全套半监督评估 + 大屏
./cc '$PY scripts/pipeline.py --csv data/data.csv --task anomaly --label-col label'

# 无标签 → 自动降级无监督，只出预警、绝不产出 AUC
./cc '$PY scripts/pipeline.py --csv data/nolabel.csv --task anomaly'

# 时序预测回测（TimesFM）
./cc '$PY scripts/pipeline.py --csv data/series.csv --task forecast --target-column value --horizon 24'
情形 01

有标签 → 半监督

前段只留正常样本作 train,其余带真值作 test,走全套评估。

情形 02

无标签 → 降级

yte 填哨兵 -1,下游跳过一切有监督指标,只出异常分与预警排名。

情形 03

过短 → 冷启动

切不出有效训练池时,全量既作参考也作检测,如实标注设定。

⚖️

诚实口径(不可违背)

数据类别极不平衡——故障仅占 7.6%,全预测「正常」的平凡基线 accuracy 就有 92.42%。因此以 AUC 0.9709 / Recall 83.27% / Balanced Acc 89.71% 作为真实证据,所有数字由 fault_warning.py 与独立 evaluate.py 双脚本交叉验证,run_id 可确定性复现。无标签时绝不产出有监督指标。
